# 採用LINE・ATSシステム 要件定義書 v1（原文）

> 依頼者から提示された要件定義書の原文を、設計の一次情報として保存したもの。
> 設計側の解釈・補足は本ファイルには書かず、`01`〜`05` の各設計ドキュメントに記載する。

## 1. システムの目的

NAORUの採用活動における、LINE登録から応募、面談、店舗見学、最終面談、内定、内定承諾、入社までの情報を一元管理する。

従来、LINE、Messenger、Zoom、各種フォームなどに分散していた採用情報を統合し、採用担当者が「誰が、今、どのフェーズにいるのか」をリアルタイムで把握できる状態を作る。

また、LINE公式アカウントとAPI連携し、応募前の見込み候補者に対して、資格や悩みに応じたシナリオ配信を行えるようにする。

## 2. 基本システム構成

新規で採用専用のLINE公式アカウントを作成する。基本構成は以下。

```
LINE公式アカウント
↓
LINE Messaging API / Webhook
↓
独自採用管理システム
↓
候補者DB / ATS / LINE配信 / 管理画面
```

技術構成については特定技術を固定せず、Claude Codeに以下を満たす最適な構成を提案・採用させる。

- LINE Messaging APIとの連携が安定して行える
- 将来的な機能追加がしやすい
- 採用データを安全に管理できる
- 開発・保守がしやすい
- API連携が追加しやすい
- 管理画面が高速に動作する

現段階では他社向けSaaS化、複雑なマルチテナント機能、高度な権限管理は優先しない。

## 3. 採用フロー

新卒・中途ともに基本フローは共通とする。

```
LINE応募 → 一次面談 → 二次面談＋店舗見学 → 三次面接＋最終面談
→ 内定 → 内定承諾 → 入社予定 → 入社済み
```

一次面談は原則応募者全員に実施する。

- 一次面談：形式 Zoom / 担当 佐藤拓磨
- 二次面談＋店舗見学：担当 見学店舗の院長
- 三次面接＋最終面談：担当 店舗オーナー

配属・紹介先判断は本部メンバーである以下3名を中心に判断する。

- 佐藤拓磨
- 若林
- 八尋

## 4. 候補者ステータス管理

単純な採用結果だけではなく、「現在どのフェーズで、どの状態なのか」を管理する。例：

LINE登録 / アンケート未回答 / アンケート回答済み / 未応募 / 応募済み / 一次面談待ち / 一次面談予定 / 一次面談実施済み / 店舗マッチング中 / 店舗見学待ち / 店舗見学予定 / 店舗見学済み / 最終面談待ち / 最終面談予定 / 最終面談済み / 内定 / 内定承諾 / 入社予定 / 入社済み / 辞退 / 不採用

候補者がどのフェーズに何名いるのかをリアルタイム集計する。

## 5. 応募フォーム

現在LINE上で取得している情報をフォーム化する。

**基本情報**：氏名 / 年齢 / 資格 / 施術歴 / 顔写真 / 最寄り駅

**現職・前職情報**：前職または現職の会社名 / 店舗名 / 転職理由 / 前職給与 / 前職勤務時間 / 前職休日日数

**希望条件**：勤務希望エリア / 転職希望時期

**その他**：家庭状況 / 聞きたいこと / NAORUを何で知ったか / Instagramアカウント / Xアカウント

**面談希望**：Zoom一次面談希望日時を第3希望まで取得する。

## 6. 応募確定時の処理

応募フォーム送信後、自動で以下を実行できるようにする。

- 応募済みステータスへ変更
- 必要タグの付与
- 応募完了メッセージ送信
- 指定動画の送信
- 一次面談管理へ移行

## 7. LINE友だち管理

LINE登録者全員を管理対象とする。応募者だけでなく、まだ応募していない見込み候補者も管理する。候補者ごとに以下を保持する。

- LINEユーザー情報 / 登録日 / アンケート情報 / タグ / 応募状況 / 選考状況 / トーク履歴 / 配信履歴 / フォーム回答履歴

## 8. タグ管理

LINE登録者全員にタグ付けできるようにする。主なタグ例：

- 資格：柔道整復師 / 鍼灸師 / 理学療法士 / その他
- 採用区分：新卒 / 中途
- 悩み：給料 / 労働時間 / 休日 / キャリア / 技術 / 人間関係 / その他
- 希望条件：希望エリア / 転職時期
- 行動：アンケート済み / 応募済み / 動画視聴対象 / 選考中 / 内定
- 流入：Instagram / YouTube / 求人媒体 / 既存LINE / 紹介 / その他

タグは管理画面から自由に追加・編集・削除可能とする。

## 9. 初回アンケート

LINE友だち追加後、「挨拶 → アンケート」という導線を基本とする。アンケートでは、応募に必要なすべての情報を取るのではなく、シナリオ配信に利用する属性を中心に取得する。

主な取得項目：新卒/中途 / 資格 / 現在の悩み / 希望エリア / 転職検討時期 / NAORUを何で知ったか

回答内容に応じて自動でタグ付けする。

## 10. シナリオ配信

LINE登録者の資格・悩み・状態に応じて自動配信する。

例：「柔道整復師」タグ＋「労働時間」タグの場合、柔道整復師の1日密着 / 電子カルテや業務効率化の紹介 / 実際の勤務時間 / スタッフの声 / 応募案内 などを配信する。

「給料」に悩みがある場合は、報酬制度 / 評価制度 / 個人ごとの報酬設計 / キャリアアップ事例 などを訴求する。

**シナリオ仕様**：1人が複数シナリオに同時参加可能（例：柔道整復師シナリオ・労働時間シナリオ・中途採用シナリオを同時実行）。

将来的に以下も設定可能にする：開始条件 / 停止条件 / 配信間隔 / 配信日時 / 配信優先順位 / 1日あたり送信数 / 重複配信防止

**選考シナリオ停止条件**：候補者が「内定」ステータスになった時点で、選考中シナリオを自動停止する。

## 11. テンプレート管理

LINEで利用する文章、画像、動画、URL等をテンプレートとして保存する。

テンプレート例：初回挨拶 / 応募完了 / 一次面談案内 / 店舗見学案内 / 最終面談案内 / 内定通知 / 給与訴求 / 労働時間訴求 / 福利厚生 / 採用PV / 1日密着

シナリオ配信、個別トーク、リッチメニューなどから同じテンプレートを利用できるようにする。

## 12. リッチメニュー

管理画面からリッチメニューを作成・設定可能にする。

基本仕様：リッチメニュー画像をアップロード / 画像上に複数のクリック領域を作成 / 四角形領域を自由に設定 / 各領域にアクションを設定

アクション例：テンプレート送信 / URLを開く / 応募フォームを開く / アンケートを開く / タグを付ける / シナリオ開始 / 別リッチメニュー切替

## 13. 1対1トーク

LINE登録者との個別トークを管理画面から行えるようにする。

主な機能：トーク一覧 / 未対応表示 / 個別トーク / テンプレート挿入 / 候補者情報表示 / タグ表示 / 選考ステータス表示

## 14. 面談評価

一次面談後、候補者ごとに評価を入力する。

**5段階評価**：人柄 / 話し方 / 経験 / 技術 / 志望度 / 長期勤務可能性 / NAORUとの相性

**その他**：総合評価 A / B / C、良かった点、懸念点、次の担当者に確認してほしいこと、院長を任せられそうなレベルか、自由記述メモ

将来的に、これらの評価データと入社後の成果を比較分析できる構造にする。

## 15. Zoomアーカイブ

Zoom録画ファイル自体はシステムへ保存しない。候補者情報に以下を保存する。

- Zoom録画URL / パスコード / 面談日時 / 面談種別

Zoomクラウド上の録画を参照する方式とする。

## 16. 店舗・エリアマッチング

一次面談後、本部で候補者の配属候補エリアを検討する。現時点では店舗単位よりも「エリア」管理を中心とする。

候補者を複数のオーナーへ順番に紹介するケースを想定する。

```
候補者A → Aオーナーへ紹介 → 見送り → Bオーナーへ紹介 → 面談希望
```

この紹介履歴を候補者ごとに記録する。記録項目例：紹介先 / 紹介日 / 反応 / 採用したい / 見送り / コメント

候補者自体の「不採用」と、店舗単位の「見送り」は区別する。

## 17. 採用結果管理

最終結果：採用 / 辞退 / 不採用

採用終了時には理由・詳細を記録できる。理由例：他社内定 / 給与条件 / 勤務地 / 入社時期 / 人柄 / 経験 / 技術 / 資格 / 連絡不通 / 本人都合 / 店舗都合 / その他

自由記述メモも保存可能とする。

## 18. 内定・入社管理

内定後も管理を継続する。管理項目：給与 / 雇用形態 / 勤務地 / 入社日 / 東京セミナー参加有無 / 内定承諾 / 入社予定 / 入社済み

## 19. 採用ダッシュボード

管理画面トップに現在の採用状況を表示する。トップを開いた瞬間に、採用担当者が現状を把握できることを重視する。

表示例：2026年内定済み / 現在選考中 / 応募済み / 一次面談待ち / 一次面談予定 / 店舗見学待ち / 店舗見学予定 / 最終面談待ち / 内定 / 内定承諾 / 入社予定

各数字をクリックすると該当候補者一覧を表示する。

フィルター：全体 / 新卒 / 中途 / 年度 / 資格 / エリア

## 20. 採用ファネル

以下のファネルを表示する。

```
LINEリスト数 → 応募数 → 一次面談 → 店舗見学 → 最終面談 → 内定 → 内定承諾 → 入社
```

人数と各ステップの転換率を表示する。

## 21. 候補者検索

以下の条件で絞り込み可能とする。

新卒/中途 / 資格 / 希望エリア / 最寄り駅 / 転職時期 / 選考フェーズ / 総合評価 / 院長候補 / 流入経路 / タグ

## 22. 管理画面UI

Lステップの管理画面を参考に、左側に機能別サイドメニューを配置する。中央部分はトップページでは採用ダッシュボードを表示する。

サイドメニュー案：

- 採用管理：候補者一覧 / 選考進捗 / エリアマッチング / 内定・入社管理
- LINE：1対1トーク / シナリオ配信 / 一斉配信 / テンプレート / 回答フォーム / リマインド配信
- 候補者属性：タグ管理 / 友だち情報 / 検索
- コンテンツ：登録メディア / リッチメニュー
- 分析：採用ダッシュボード / 流入分析 / 選考分析 / 入社後分析
- 設定：LINE公式アカウント設定 / 採用フロー設定

## 23. リマインド配信

初期優先度は低めとする。将来的に以下を自動化する。

一次面談前日 / 店舗見学前日 / 最終面談前日 / 面談当日 / キャンセル時 / 内定後

初期段階ではまずテンプレート機能を作り、手動送信でも運用可能にする。

## 24. 将来的な入社後分析

内定・入社データと、入社後の業績データをAPI連携できる構造を想定する。

分析例：どの資格の人が成果を出しているか / どの面談評価の人が活躍しているか / 人柄評価と定着率 / 技術評価と売上 / 流入媒体別の活躍度 / 早期離職者の特徴 / 院長候補評価と昇格率

初期開発では実装しないが、後から候補者IDと従業員データを紐付けられる設計とする。

## 25. 初期管理者

初期段階では主に以下の2名が全機能を利用する。

- 佐藤拓磨
- 若林

複雑な権限管理は初期開発では優先しない。

## 26. 実装フェーズ

**Phase 1：採用管理基盤**（優先して実装）

LINE公式アカウントAPI連携 / LINE友だち管理 / アンケート / 応募フォーム / タグ管理 / 候補者一覧 / 候補者詳細 / 選考ステータス管理 / 面談評価 / Zoomアーカイブ情報管理 / 店舗・エリア紹介履歴 / 内定・入社管理 / 採用ダッシュボード / 採用ファネル / 個別トーク / テンプレート / リッチメニュー

**Phase 2：自動化**

シナリオ配信 / 条件分岐 / 自動タグ / 一斉配信 / リマインド / 配信停止条件 / 配信優先順位 / 重複配信防止 / Zoom等との追加連携

**Phase 3：高度分析・連携**

詳細採用分析 / 流入分析 / 入社後データAPI連携 / 活躍人材分析 / 早期離職分析 / 高度な自動化

## 27. Claude Codeへの開発方針

この要件定義書を渡した直後に、すべての実装を開始しない。最初にClaude Codeへ以下を実施させる。

1. 要件定義を理解する
2. 最適な技術構成を提案する
3. システムアーキテクチャを設計する
4. データベース構造を設計する
5. 各テーブル・データの関連性を提示する
6. LINE Messaging APIとの連携方法を設計する
7. Phase 1の実装計画を作成する

この内容を人間側で確認した後、Phase 1の実装を開始する。技術構成はClaude Code側に最適なものを選定させる。
