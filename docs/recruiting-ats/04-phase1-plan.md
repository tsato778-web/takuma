# 04. Phase 1 実装計画

対象：要件定義書 v1 第26章（Phase 1）／第27章（開発方針 7）

---

## 1. Phase 1 のゴール

**「LINE 友だち追加から入社までの全情報が1画面群で追え、採用担当者が毎朝ダッシュボードを開けば現状が分かる状態」** を作る。

自動配信（シナリオ・一斉配信・リマインド）は Phase 2 だが、**テンプレートと1対1トークを Phase 1 に含めることで、手動運用でも実務が回る**状態にする（要件23の方針に一致）。

### Phase 1 に含むもの（要件26のとおり）

LINE公式アカウントAPI連携 / LINE友だち管理 / アンケート / 応募フォーム / タグ管理 / 候補者一覧 / 候補者詳細 / 選考ステータス管理 / 面談評価 / Zoomアーカイブ情報管理 / 店舗・エリア紹介履歴 / 内定・入社管理 / 採用ダッシュボード / 採用ファネル / 個別トーク / テンプレート / リッチメニュー

### Phase 1 に含まないもの（明示）

- シナリオ配信の自動実行、条件分岐、配信優先順位、重複配信防止、1日あたり送信数制御 → Phase 2
- 一斉配信、リマインド自動配信 → Phase 2（テンプレートからの手動送信で代替）
- Zoom API 連携（録画URL・パスコードは手入力） → Phase 2
- 流入分析・選考分析の詳細画面、入社後分析 → Phase 3（データ蓄積の構造のみ Phase 1 で用意）
- 細かい権限管理、複数テナント対応 → 対象外（要件2・25）

## 5. 品質基準

| 観点 | 基準 |
| --- | --- |
| 性能 | 候補者一覧（5,000件規模）の初期表示 1秒以内、ダッシュボード 1.5秒以内 |
| 信頼性 | Webhook の取りこぼしゼロ（生ログ保存＋再処理可能）。送信失敗は必ず記録され通知される |
| データ整合性 | フェーズ変更は必ず履歴が残る。応募確定処理は二重実行されない |
| セキュリティ | 未ログインでの管理画面アクセス不可。顔写真は署名付きURLのみ。監査ログ記録 |
| テスト | 選考フェーズ遷移・応募確定処理・署名検証・配信ジョブの単体テスト、主要3導線の E2E |
| 対応環境 | PC（Chrome / Safari 最新）。候補者向け LIFF はスマートフォン最適化 |

## 6. リスクと対策

| リスク | 影響 | 対策 |
| --- | --- | --- |
| LINE アカウント開設・チャネル発行の遅れ | Sprint 1 以降が全て遅延 | Sprint 0 の最優先タスク。検証用チャネルを先行作成して開発を進める |
| 既存アカウントからの友だち移行ができない | 見込み候補者リストを引き継げない | LINE 仕様上、友だちリストの移行は不可。既存アカウントからの誘導配信を計画（`05` 参照） |
| 要件5・9のフォーム項目が運用中に変わる | 改修コストが継続発生 | フォーム項目を DB 定義にし、管理画面から追加・変更できる設計にする（Sprint 3） |
| 採用フェーズの定義変更 | 集計ロジックの破壊 | フェーズをマスタ化し、集計は `kind` / `funnel_step` を参照。表示名変更は集計に影響しない |
| 配信通数の増加によるコスト増 | 月額費用の想定超過 | 残メッセージ数の可視化を Phase 1 の設定画面に含め、Phase 2 の配信設計時に上限制御を必須にする |
| 院長・オーナーが評価を直接入力する運用になった場合 | 権限管理が必要（Phase 1 対象外） | 当面は本部メンバーが代理入力する運用を想定。要確認事項として `05` に記載 |
| 顔写真・給与など機微情報の取り扱い | 情報漏洩リスク | 非公開バケット＋署名付きURL、監査ログ、保存期間ポリシーの策定（`05` 参照） |

## 7. Phase 2 以降への引き継ぎ設計（Phase 1 で仕込むこと）

Phase 1 の実装時点で、以下は「テーブルと接続点だけ」用意しておく。後から作り足す際の手戻りを防ぐため。

| Phase 2/3 の機能 | Phase 1 で用意するもの |
| --- | --- |
| シナリオ配信 | `message_jobs`（キュー基盤）、`templates`、タグ・フェーズの機械可読な定義。配信条件の評価対象となるデータが揃った状態 |
| 配信停止条件（内定で停止） | フェーズ変更時にフックを呼べる共通処理（`lib/pipeline`） |
| リマインド配信 | `interviews.scheduled_at`（面談日時が構造化データとして存在すること） |
| 入社後分析 | `employee_links` テーブル、`interview_evaluations` の項目別スコア列、`candidate_stage_histories` |
| 流入分析 | `candidates.source` と友だち追加経路の記録 |
| Zoom API 連携 | `interviews.zoom_meeting_id` 列 |
