# リピスト 引き継ぎドキュメント（スレッド分割用）

> アプリ本体は `repisuto/`（Next.js 14 App Router / TypeScript / Tailwind / Radix Dialog / lucide-react）。
> 現状すべて**モックUI**（DB未接続・状態はセッション内のみ・リロードで初期化）。モック上の「今日」は 2026-05-27/28 固定。
> 開発ブランチ: `claude/awesome-feynman-FhMo5`（PR #6）。思想の正本は `CLAUDE.md`。

## 1. リピスト全体思想
- 目的：美容室・整体・リラク・エステ・ネイル等**サロン系店舗のリピート率最大化**。
- 「ただの予約/CRM」ではなく **“リピートを科学するOS”**。来店前・中・後の**感情設計／行動設計をシステム化**。
- 「人が頑張る」のではなく **システム側で再来店を自動設計**（LINE中心）。
- 一気通貫データ：**誰が・どの媒体から来て・どんな悩みで・何を予約し・何を買い・次回予約につながったか**を顧客×店舗×媒体で追える。
- 売上は常に2系統：**総売上ベース（決済額＝CF）** と **消化売上ベース（役務提供）**。回数券は購入売上と消化売上を分離。
- UIトーン：美容クリニック系の高級感（白ベース・上品・余白）＋現場が迷わず高速操作。

## 3. 予約台帳の仕様（`reservation-board` / `reservation-block` / `new-reservation-dialog` / `reservation-detail-dialog`）
- 横軸=時間（営業9:00–20:00, 粒度15/30/60分）、縦軸=スタッフ。ドラッグ移動・端リサイズ。
- 枠種別＝予約/休憩/ミーティング/ブロック/その他（`Reservation.kind`）。予約以外はダークアウト表示・予約不可。
- カードは「顧客名（全文）→コース名→開始時間/タグ」。コース別カラー（メニュー色）、新規はNEWリボン、未会計/未カルテ/LINE未/回数券残バッジ。
- **インターバル（準備時間）**：施術＋インターバルで占有。売上・コース表示は施術時間のみ（`intervalMin`）。カードに準備帯（斜線）。
- **二重予約**：作成時に同一スタッフ重複を検出→警告モーダル（重複相手提示）→「それでも作成」。台帳上は赤枠＋「重複」。**判定はスタッフ単位の担当ブロック時間**。
- **複数担当（担当分担／施術リレー）**：1予約に `assignments[]`（役割 主/サブ/補助・担当メニュー・開始/終了・売上配分share）。台帳は**担当ブロックごとに別行で分割描画**（主=通常カード、続き=左端シェブロン＋「◯◯様の施術の続き」、補助=薄カード）。空き判定も担当ブロック単位（例：主担当は自分の区間後は空き）。
- **スタッフ×メニュー**：`Staff.menuIds`。対応不可メニューは予約作成で選択不可、台帳で「担当不可」警告。
- **メニュー別担当割り当て**：作成モーダルで2メニュー以上のとき、メニューごとに担当を選択（時間自動）＋補助追加→`assignments` 生成。
- **新規顧客として予約（電話予約）**：顧客欄トグルで氏名/カナ/電話/メール/流入経路入力、電話番号で重複チェック→候補紐付け、予約完了通知＋問診票URL送信トグル（モック）。
- **キャンセル**：事前/当日/無断（`cancelType`）。半透明・取消線で履歴保持。顧客予約画面では空き扱い（`occupiesSlot`）。KPI用に種別保持。
- **会計**：詳細から「会計する（自動で来店済）」。会計済みは「会計を修正」で再オープン可。
- **スタッフ稼働**：スタッフ名下に「予約N件・稼働X%」（分母=勤務−休憩/ブロック/会議、複数担当は担当ブロック加算、ホバーで内訳）。
- 日付：DatePicker（月カレンダー）。日毎メモバー（店舗全体/個人・終日/時間指定・色分け）。

## 4. 顧客管理の仕様（`customer-detail` / `customer-drawer` / `/customers`）
- ハイブリッド：台帳/一覧クリック→**右ドロワー**→「詳細を開く」→**フルページ**。
- ヘッダー：顧客No/氏名/カナ/電話/性別/生年月日+年齢/LINE連携/初回媒体/登録メディア/流入経路/顧客タグ/メッセージタグ/LTV/最終来店/次回予約/回数券残/月額会員/担当（主/初回/前回/次回）/属性タグ。
- タブ：基本情報・来店履歴・カルテ・会計・回数券・LINE・AI戦略・回答フォーム・分析（9）。
- 一覧：KPIカード（総数/次回予約率/回数券保有率/離反リスク）、回数券残・次回予約日時の列、**離反リスク（回数券0×次回予約なし）=薄赤＋要フォロー**、並び替え、複数フィルタ（回数券/次回予約/離反/VIP/新規/媒体/タグ/**担当者×役割**）、横断検索（No/氏名/カナ/電話/LINE名）。
- 離反/ファン化：`isChurnRisk`、回数券トーン（残1黄/残0赤）、口コミタグ（Google/HPB）。

## 5. カルテの仕様（`customer-chart` / `chart-detail-dialog` / `lib/charts.ts`）
- **2系統に分離**：①お客様入力カルテ（初回問診・顧客1件・**フォームビルダー前提のセクション×フィールド構造**）②スタッフ入力カルテ（来院ごとに蓄積）。
- スタッフ記録：**左=来院履歴／右=その日の詳細**。SOAP（S/O/A/P）＋施術内容/使用薬剤/施術メモ/次回提案/注意事項/写真＋会計/回数券消化/次回予約。記入済/下書き/未記入ステータス。
- `/records` は管理一覧（記入待ちKPI・担当/ステータス/検索）。AI戦略は両カルテを参照する設計。

## 6. 会計の仕様（`checkout-dialog` / `/pos` / `lib/pos.ts`）
- 明細：施術（予約メニュー自動）＋店販/オプション/回数券購入/サブスク/入会金/クーポン/値引き(固定%手入力)/端数調整/紹介特典/**回数券消化**（種類別・残/期限・消化単価）。
- 担当：施術/会計/回数券販売/回数券消化を個別保持。**売上配分**（複数担当時%手入力・各「100%計上」ボタン・合計100%警告・主担当初期100%）。
- 支払い：クレジット先頭・現金/PayPay/QR/ホットペッパーポイント/その他、**全額自動入力**＋複合払い（残額自動充当）。
- 売上区分：会計済み売上/回数券消化売上（別計上）/回数券購入売上/技術/店販/会員/担当売上/店舗売上/総売上。
- 口コミ取得チェック→顧客タグ自動付与。会計確定で `CheckoutSummary` を集計へ連携。完了画面で次アクション（次回予約/LINE/カルテ/回数券提案/口コミ/AI）＋AI提案。会計済みは「会計を修正」で再編集（履歴/権限は方針のみ）。

## 7. KPI分析の仕様（`/analytics` / `lib/analytics.ts`）
- **経営者ビュー / 現場ビュー** 切替＋スタッフ絞り込み。期間：日/週/月/任意（カレンダー）。軸：店舗全体/担当者別/メニュー別/媒体別/新規・再来。
- 売上区分（会計済み/消化ベース/総売上、回数券購入/消化分離）、決済種別内訳、次回予約率、**リピート率（後日再来ベース・全体/初回/再来）**、客単価。
- 担当者ランキング（会計済/消化/回数券販売/次回予約率/リピート率/回数券販売率）、日別推移、メニュー別、媒体別（LTV・回数券率）。
- **月末着地予測**（総売上/消化売上ベース・会計済/予約済見込み/回数券/新規/各率・目標達成率/不足額/必要新規・回数券・次回予約数）。**Meta広告 予算シミュレーター**（CPA/初回単価/回数券率/LTV入力→想定新規/売上/ROAS/着地）。
- 現場ビュー：会計待ち/未カルテ/次回予約未取得/回数券残1＋要フォロー顧客リスト＋口コミ取得数。
- データは合成取引（`TXNS` 2026/04–05）。本実装では会計・予約データを集計源に差し替え。

## 8. LINE / CRM / ポイントの思想
- **LINEマイページ（ミニアプリ前提・アプリ不要）**：ポイント/来店回数/次回予約/回数券残/VIPランク/担当/履歴/おすすめ/限定クーポン/紹介・口コミ特典。お客様には内部情報を見せず「また来たくなる情報」だけ。
- **ポイント**：割引目的にしない。来店/口コミ/紹介/誕生日で付与し、**限定メニュー解放・先行予約・回数券更新特典・体験価値・VIP感**へ交換。ファン化ランク（新規→継続→優良→VIP→ファン）。
- **状態別配信（最重要）**：属性ではなく「顧客の状態」（初回×次回予約有無/回数券残1/60日未来店/VIP/口コミ未/離反リスク等）→トリガー→配信内容→自動アクション。状態が変わると配信フローが自動切替。
- 自動トリガー：来店直後/翌日/3/7/30/60日/誕生日/回数券残/次回予約有無/口コミ・紹介/特定メニュー後。
- パーソナライズ：担当名/メニュー/悩み/前回会話/来店周期/おすすめ/前回提案。
- 配信KPI：再来率/次回予約率/回数券更新率/開封率/クーポン利用/口コミ/紹介/LTV/失客復帰率を施策別に計測。
- 強制リンク：媒体×CP×訴求×メニュー×タグ×テンプレでURL発行・一括生成。経由予約は媒体タグを顧客/予約/会計/LTVへ引き継ぐ。回答フォーム回答→顧客/タグ/LINE/AI/KPIへ連携。

## 9. DB設計で重要な前提（現状の型＝将来テーブルの素案）
- 全エンティティ `storeId` 保持（多店舗・将来 `brandId` も）。番号は一意採番：**顧客No**（4桁ゼロ埋め）、**スタッフ番号 S0001…（システム全体で一意・退職後も保持＝論理削除）**。
- `Reservation`：kind/customerId?/staffId/menuIds/start/end/intervalMin/status/cancelType?/source/isNominated/paid/hasChart/**assignments[]**（複数担当）。予約可否・稼働率は assignments（担当ブロック）基準。
- `Assignment`：staffId/role(MAIN/SUB/ASSIST)/label(担当メニュー)/start/end/share(売上配分)。→ スタッフ別売上・KPIの源泉。
- `Customer`：No/氏名/カナ/性別/生年月日/電話/firstSource/registerMedia/funnel/tags/messageTags/ltv/最終来店/次回予約/担当(main/first/last)/月額会員/lineLinked/lineName/tickets[]/visitCount。
- `Ticket`：種類別（totalCount/remaining/durationMin/**unitPrice=消化単価**/validUntil/menus）。購入売上と消化売上を分離。
- `Menu`：durationMin/**intervalMin**/price/color/（将来：カテゴリ/区分/受付可能数/対応スタッフ/表示/回数券対象/画像）。`Staff.menuIds`＝対応可能メニュー。
- `ChartRecord`（来院ごと・SOAP）＋ お客様入力カルテ（フィールド配列）。`FormField/SurveyForm`（フォームビルダー）。`ForceLink`（UTM/媒体タグ）。会計は `LineItem`＋`CheckoutSummary`（収受/消化/購入/支払/担当）。
- 売上2系統（総売上＝収受、消化売上＝役務）を必ず分離。KPIは実績＋着地予測。

## 10. 未実装・今後やるべきタスク
- **LINE実装**：状態別配信の自動トリガーエンジン、Messaging API連携、配信→KPI実測、マイページ(LIFF)。
- **ポイント/会員**：付与・交換ロジック、VIPランク自動判定、サブスク管理。
- **会計修正の監査**：差分/操作履歴(誰がいつ)・締め後は責任者権限。通知の「送信済/問診未入力」状態を台帳・顧客に表示。

- **メニュー別売上配分**：明細ごとの担当割当→スタッフ別売上反映の本実装。
- **出勤表→予約可否連動**：時間指定出勤を台帳/お客様予約画面の空き判定に反映、予約開放設定の◯×反映。
- **お客様予約画面（◯×）**：重複不可・キャンセル枠は空き・スタッフ×メニュー制約・主担当のみ表示。
- **フォーム/強制リンク本実装**：回答保存→顧客/カルテ自動反映、媒体タグ引き継ぎ、フォームのセクション折りたたみ。
- **Googleビジネス連携**：GBP API（口コミ取得/返信/通知/口コミ×リピート分析）。
- **AI戦略**：離脱危険度スコア、来店周期アラート、オファー最適化、感動メモ、教育連動。
- **基盤**：DB（Prisma等）・認証・権限ロール・多店舗/ブランド切替・実データ移行（現状すべてモック）。
